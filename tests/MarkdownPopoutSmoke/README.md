# Markdown popout regression check

Run on Windows with .NET 10 and the WebView2 Runtime installed:

```powershell
dotnet run --project tests/MarkdownPopoutSmoke/MarkdownPopoutSmoke.csproj
```

This launches the real task-detail window offscreen with temporary Markdown, waits for its composition preview, and invokes the actual Expand Resource button twice. It verifies formatted Markdown in both native popouts, separate browser user-data folders, drop settings, code-copy controls and checkbox file persistence. It fails on initialization errors or plain-text fallback. It never opens the main window or accesses the user's task database.

The inline-edit checks use a long document with headings, lists and code blocks. They verify source-line/viewport anchors in both directions, edits above and near the viewport, beginning/end clamping, unsaved draft previews, Save in either mode, read-only and external-edit failures, and Discard. They also verify that embedded Edit is absent while Open remains available. Modal draft confirmations are answered only when their window belongs to this smoke process, covering popout close, owner close, resource-kind changes and failed Save during closing. The clipboard is temporarily used to verify exact code copying and then restored.

The pin checks cover exact partial formatting, multi-block selections, local persistence, overlapping checklist excerpts, multiwindow updates, independent scrolling, header-only navigation, highlight visibility, unpin, provisional draft anchors, save/discard, ambiguous external edits, and missing/restored files. Pin metadata created for the temporary source is removed after the check.

Internal dragging is exercised with uninterrupted DevTools mouse input: press/move/release selects text, a second press/move drags that existing selection, and release pins it. There is no drag interception, injected drag payload, `Input.dispatchDragEvent`, or dispatched DOM drag/drop event. Formatted text, checklist text and code are covered, with delayed left-edge reveal, leaving-edge timer cancellation, Escape cancellation, overlay positioning, hidden overlay divider, and successful drop. The earlier intercepted-drag check masked a real failure and must not be restored.

The original failure was reproduced separately using OS-level SendInput through computer-use in an isolated real native popout. Selection succeeded, but a second drag yielded `dragstart -> pointercancel -> dragend` without any target `dragenter/dragover/drop`; consequently neither pin creation nor the edge timer ran. Changing only `AllowExternalDrop` did not fix that native handoff. Pin dragging now uses pointer capture before the HTML/Windows OLE handoff, keeping both external-drop flags disabled. The same OS-input select-then-drag gesture successfully created a formatted pin after the fix. This was automated OS mouse input, not a person operating physical hardware. Timed edge dwell/cancellation is verified with uninterrupted DevTools pointer input.

Layout checks drag the divider to both bounds, preserve the reading anchor, retain width across toggles and new sessions, synchronize per-file settings across windows, and verify wrap/no-wrap horizontal scrolling for long prose, list text and code. Main-document wrapping is unchanged. Icon labels and the keyboard pin command are checked. A long final source line also exercises end-anchor retention when automatic horizontal-scrollbar layout settles just short of the final source extent; scrolling away releases that retained anchor.

For an isolated on-screen mouse check, run `dotnet run --project tests/MarkdownPopoutSmoke/MarkdownPopoutSmoke.csproj -- --manual-pins`. Only a temporary Markdown document is opened. Select text, release, drag the selection into the sidebar; with the sidebar closed, hold it within the leftmost 32 browser pixels for about one second. Leave the edge early or press Escape to cancel. Drag the divider and change Wrap text. The probe records pointer/drag events in ignored `artifacts/MarkdownPopoutSmoke/input-trace.json`. Create the empty file `artifacts/MarkdownPopoutSmoke/stop-probe` to close the probe and clean its temporary data; do not close the real user app.

Opening a native popout by itself cannot catch the shared-environment initialization failure. Do not replace the embedded-first sequence with an isolated preview, or force a resource reload after opening. This checks rendering functionality, not perceived sharpness at a particular display scaling.


Pin-management checks cover icon-only collapse/expand, per-file persistence and multiwindow updates, the actual right-click Rename menu, Cancel, whitespace validation, literal rendering of markup-like titles, and source bytes remaining unchanged. They add later passages before earlier passages and overlapping ranges to verify source-position ordering. An intact source section is moved externally, then edited/saved inline and reloaded; ordering, titles and collapsed state must survive. Unavailable passages stay after located pins without guessing a match. Clear all pins is exercised through the real current-document OK/Cancel confirmation, including collapsed/unavailable pins, cross-window empty state/highlights and retained layout preferences. Unit tests also check a second document remains untouched, concurrent metadata edits survive draft saves, and renaming an unresolved pin cannot revive a stale anchor.

For focused diagnosis, `--inline-only` skips pin checks and `--management-only` runs pin management plus inline editing; the default run always includes all checks. These switches retain the embedded-first initialization and two native popouts.
